# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A reusable Terraform **module** (not a root configuration) that creates an Azure Static Web App and binds custom domains from an existing Cloudflare zone to it: the apex via `dns-txt-token` validation and a flattened CNAME, subdomains via `cname-delegation`. It provisions infrastructure only; consumers deploy content with the `deployment_token` output. `example/` is a root configuration that consumes the module via `source = "../"`.

Consumers: `westphalia-kn.de`, `twv-westphalia.de` and `thorstensauter.dev`, referenced as `github.com/ThorstenSauter/cloudflare-azure-static-web-app?ref=X.Y.Z` and bumped by Renovate.

## Commands

No tests exist. CI (`.github/workflows/ci.yml`) runs these checks on PRs through `ThorstenSauter/terraform-actions/validate`, which also runs a Trivy config scan. To run them locally from the repo root:

```sh
terraform init -backend=false
terraform fmt -check -recursive
tflint --init && tflint --no-color -f compact   # uses .tflint.hcl (azurerm ruleset)
terraform validate -no-color
```

## Architecture (all in `main.tf`)

- **for_each keys are a contract.** The apex resources are keyed by the zone name (`apex["example.com"]`), the subdomain resources by their label (`subdomain["www"]`), and `time_sleep.dns_propagation` is `[0]`. Consumers migrated onto the module with `moved` blocks that target these addresses, so renaming a resource or changing its keys recreates the Static Web App custom domains (downtime) in every consumer. Treat any such change as breaking and ship `moved` blocks inside the module.
- The keys come from `var.cloudflare_zone_name`, not the zone data source, so they are known at plan time.
- **Ordering:** DNS records → `time_sleep` (`wait_for_dns_propagation`, default `120s`) → the `cname-delegation` custom domains, because Azure checks the CNAME as soon as the domain is created. The apex custom domain is created first, because its TXT record needs the validation token it returns. The `time_sleep` is keyed on the CNAME record IDs (`triggers`), so adding a subdomain or recreating a record waits again.
- The TXT record ignores changes to `content`, so a later token rotation doesn't show up as drift.
- Both custom domains ignore `validation_type`: Azure doesn't return it, so it is empty in state after an import, and a diff would recreate the domain.
- Records are DNS-only (`proxied = false`) so Azure can issue and renew the managed certificates, use `ttl = 1` (automatic) and carry a `comment`.
- The Static Web App ignores `repository_*` attributes because content is pushed with the deployment token, not from a linked repo.

## Conventions

- Input variables carry `validation` blocks. Keep adding validations for new inputs. New inputs should be optional with a backward-compatible default.
- The `README.md` section between `<!-- BEGIN_TF_DOCS -->` and `<!-- END_TF_DOCS -->` is generated by terraform-docs v0.24.0 (config in `.terraform-docs.yml`). Run `terraform-docs .` in the repo root and commit the result; CI fails when it is stale instead of pushing a fix, because bot commits would be unsigned. Don't hand-edit it.
- The workflow is hardened: `permissions: {}` at the top with per-job permissions, `timeout-minutes`, `persist-credentials: false`, actionlint and zizmor. `CI passed` is the only required status check, so add new jobs to its `needs`.
- `main` requires signed commits and squash merges. Release tags are protected (admins only, no updates or deletions) and releases are immutable, because consumers pin `?ref=X.Y.Z`.
- `.terraform.lock.hcl` is intentionally gitignored because this is a module.
- Releases are GitHub releases with plain `X.Y.Z` tags (no `v` prefix), following SemVer. Breaking changes bump the major version.
- GitHub Actions are pinned to commit SHAs with a version comment. Dependency updates come from Renovate (`chore(deps): ...` commits). Commit messages follow Conventional Commits.
- `.editorconfig`: LF line endings, 2-space indent, UTF-8.
